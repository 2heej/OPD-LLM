# 신경과 재진 외래 AI 문진 — 프로젝트 요약 (발표자료용)

## 한 문단 요약

외래 간호 경험에서 확인한 정보 누락, 서류 요청 지연, 보호자 단독 내원, 상담 내용 누락 문제를 바탕으로 신경과(치매·파킨슨병·뇌전증) 재진 환자 대상 AI 사전 문진을 설계하였다. 비식별 합성 사례 30건(개발 20/시험 10)과 gold 데이터를 구축하고, 동일한 모델(gpt-4.1-mini)에서 프롬프트 v0~v3의 Exact Match, Field Accuracy, Micro F1을 비교하였다. 10건 파일럿으로 방법론을 검증한 뒤 사투리·두서없는 발화·다중 요청을 포함한 30건으로 확장했으며, 대표 오류를 5개 유형(누락 오류·과잉 추론·분류 오류·표현 오류·형식 오류)으로 분석해 프롬프트를 개선하였다. 개발 세트에서 Exact Match가 5%(v0)에서 60%(v3)로, Micro F1이 0.698에서 0.949로 개선되었고, 불확실성 규칙(v2)이 오히려 성능을 떨어뜨리는 부작용도 확인하였다. 최종 프롬프트(v3)는 보지 않은 시험 세트 10건에서 Micro F1 0.912, 방문 형태 정확도 100%를 기록했다. 전 호출을 LangSmith로 트레이싱하고 버전별 실험을 데이터셋에 기록해 비교하였으며, `frontend/` 문진 UI 프로토타입으로 적용 흐름을 시연하였다.

## 핵심 수치 (2차 실행, 개발 세트 20케이스)

| 지표 | v0 | v1 | v2 | v3 |
|---|---|---|---|---|
| Exact Match | 5% | 60% | 35% | 60% |
| Field Accuracy | 38.3% | 90.0% | 80.0% | 90.8% |
| Micro F1 | 0.698 | 0.907 | 0.824 | 0.949 |
| 누락률 | 38.8% | 10.2% | 14.3% | 4.1% |
| 환각률 | 18.9% | 8.3% | 20.8% | 6.0% |
| 입력 토큰 | 6,474 | 13,214 | 15,814 | 25,394 |

시험 세트(v3, 10케이스): Exact Match 40%, Field Accuracy 83.3%, Micro F1 0.912, 방문 형태 정확도 100%.

1차 파일럿(10케이스, 쉬운 세트)에서는 v3가 Exact Match 85.7%, Micro F1 1.000 — 케이스를 어렵게 확장하자 점수가 내려간 것 자체가 "쉬운 세트의 높은 점수는 일반화를 보장하지 않는다"는 발표 논점.

## 발표 스토리라인

1. **문제 정의는 현장에서**: 외래 접수에서 반복되는 네 가지 문제(정보 누락, 서류 지연, 보호자 단독 내원, 상담 내용 누락)를 LLM 구조화 요약으로 완화할 수 있는지 검증. 서비스 구축이 아니라 프롬프트 설계·평가가 목적.
2. **버전별 개선 서사와 반전**: v1(필드·허용값 명시)이 가장 큰 개선을 만들었고, v2(불확실성 규칙)는 오히려 v1보다 하락 — '명시 없으면 유보' 규칙이 지저분한 문장에서 명시된 정보까지 유보하게 만듦. "규칙 추가는 공짜가 아니며 평가로 검증해야 한다"는 논점. v3(도메인 규칙)는 누락률 최저(4.1%)로, 누락 최소화가 최우선인 문진 목적에 맞아 최종 선택.
3. **평가가 설계를 바꾼 사례**: smoke test 오분류를 보고 증상 변화 판정 기준을 v3에 추가, 프롬프트 예시와 평가 케이스가 중복되던 데이터 누수 발견·수정. 확장 평가에서는 '나빠짐 vs 새 증상' 경계가 최다 오류로 확인돼 — gold 작성 때 사람도 고민한 경계 — '양상 변화' 중간 카테고리 신설을 다음 개선 과제로 도출.
4. **파일럿→확장의 간극**: 10건 파일럿에서 v3는 Micro F1 1.000이었으나 사투리·다중 요청·희소 라벨을 넣은 30건에서 0.949로 하락. 쉬운 세트의 만점이 일반화를 보장하지 않음을 스스로 검증한 과정.
5. **비결정성과 이중화**: "저만 왔어요" 케이스를 smoke test에서는 맞히고 본 실행에서는 두 차례 모두 틀림. 방문 형태처럼 행정·안전에 민감한 필드는 프롬프트만으로 보장할 수 없어, 문진 UI의 방문 형태 선택값을 신뢰 소스로 쓰는 이중화를 설계에 반영.
6. **UI 설계 판단**: 증상 변화(선택형)는 약 처방만 받으러 와도 확인(재진에서 "변화 없음" 확인 자체가 기록 가치), 서술형 입력은 증상 상담 선택 시에만 노출(입력 부담 최소화). 임상 안전망과 UX 부담의 절충.
7. **실험 관리 도구**: 전 호출을 LangSmith로 트레이싱(토큰·지연시간·프롬프트 원문)하고, 저장된 예측을 API 재호출 없이 데이터셋 실험으로 기록해 v0~v3 비교 대시보드 구성 — 비용 의식적 설계.
